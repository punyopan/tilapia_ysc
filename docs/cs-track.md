# สาขาวิทยาการคอมพิวเตอร์ — แผนการปรับ / Making this win in the CS track

สาขาถูกล็อกไว้ที่วิทยาการคอมพิวเตอร์แล้ว เปลี่ยนไม่ได้ ดังนั้นต้องปรับให้งานนี้
**ชนะในสาขาคอมพิวเตอร์** ไม่ใช่เสียใจที่ไม่ได้ส่งสาขาสิ่งแวดล้อม

The track is fixed. So the job is not to regret it — it is to make the project
a genuine CS entry. That is achievable, and most of the work already exists. One
thing has to change, and one thing has to be built.

---

## การปรับกรอบ / The reframe

| | เดิม | ใหม่ |
|---|---|---|
| สิ่งที่ประเมิน | แบบจำลองการแพร่กระจาย | **ระบบสกัดและระบุตำแหน่ง** |
| ปลาหมอคางดำคือ | หัวข้อของงาน | **โดเมนที่ใช้ประเมินระบบ** |
| ข้อค้นพบเชิงนิเวศ | ผลลัพธ์หลัก | **การประเมินปลายทาง (extrinsic)** |

**The resolver is the contribution; the fish is the evaluation domain.** That is
not a demotion of the ecology — applied NLP evaluated on a real domain is a
completely normal CS project shape. The ecological result becomes your
*extrinsic evaluation*, which is a stronger position than it sounds: you can
show that better extraction produces better downstream inference, which most
NLP papers cannot.

---

## ข้อเสนอที่ทดสอบได้ / The testable systems claim

สถาปัตยกรรมของระบบเป็นแบบผสม (hybrid neural-symbolic) คือ **แบบจำลองภาษารายงาน
ชื่อสถานที่ตามตัวอักษร ไม่ระบุรหัสเอง** แล้วให้ตัวจับคู่เชิงกฎเป็นผู้ระบุ

ทางเลือกที่ง่ายกว่าและคนส่วนใหญ่จะทำคือ ให้แบบจำลองภาษาตอบรหัสตำบลมาเลย

> **H0:** ถามแบบจำลองภาษาตรง ๆ แม่นยำเท่ากับสถาปัตยกรรมผสม
> **H1:** สถาปัตยกรรมผสมแม่นยำกว่า และความต่างกระจุกอยู่ในกรณีที่กำกวม

นี่คือข้อเสนอเชิงระบบที่วัดผลได้ และเป็นสิ่งที่กรรมการสาขาคอมพิวเตอร์ประเมินได้จริง
— ต่างจาก "ผมสร้าง pipeline" ซึ่งประเมินไม่ได้

---

## สิ่งที่ยังขาด: ชุดข้อมูลทดสอบที่ติดป้ายด้วยมือ

**นี่คือช่องว่างเดียวที่สำคัญ** ไม่มีชุดนี้ก็ไม่มีงานวิจัยเชิงคอมพิวเตอร์

This is the one real gap. Without a labelled test set there is no CS result —
only an assertion. `benchmark.py` is the harness; you supply the data.

### ขนาดและวิธีทำ

- **300–500 mentions** จากข้อความไทยจริง มากพอให้ค่าความแม่นยำรายประเภทมีความหมาย
  (ตั้งเป้าอย่างน้อย 30 ต่อประเภท) แต่ยังทำเสร็จได้ในไม่กี่วัน
- สุ่มจากคลังข้อความจริง **อย่าเลือกเฉพาะกรณีที่น่าสนใจ** เพราะจะทำให้สัดส่วน
  ความยากไม่ตรงกับของจริง
- ติดป้ายรหัสตำบล/อำเภอ/จังหวัดที่ถูกต้อง **และประเภทความกำกวม**
- ที่สำคัญที่สุด: ติดป้าย **`gold_code = None`** เมื่อคำตอบที่ถูกต้องคือ
  "ระบุไม่ได้" รายการเหล่านี้คือหัวใจของการวัด ระบบที่ตอบทุกครั้งจะได้คะแนนดีใน
  รายการที่ระบุได้ และกุตำแหน่งขึ้นมาในรายการที่เหลือ
- ให้คนที่สองติดป้ายซ้ำ **50 รายการ** แล้วรายงานค่าความสอดคล้องระหว่างผู้ติดป้าย
  (Cohen's kappa) กรรมการสาขาคอมพิวเตอร์จะถามเรื่องนี้

### ประเภทความกำกวม (taxonomy)

| ประเภท | คำอธิบาย | ทำไมวิธีมาตรฐานถึงพลาด |
|---|---|---|
| `unique` | ชื่อไม่ซ้ำ | — |
| `prefix` | ต./ตำบล/เว้นวรรค | ภาษาไทยไม่เว้นวรรคระหว่างคำ |
| `collision` | ชื่อตำบลซ้ำข้ามจังหวัด | สตริงอย่างเดียวไม่พอ ต้องใช้บริบท |
| `mueang` | อ.เมือง ลอย ๆ | ฐานข้อมูลเขียน เมือง<จังหวัด> ข้อความเขียน อ.เมือง |
| `alias` | ชื่อพ้องท้องถิ่น (แม่กลอง) | edit distance กู้คืนไม่ได้ |
| `typo` | OCR / พิมพ์ผิด | — |
| `unresolvable` | **ระบุไม่ได้ และไม่ควรตอบ** | ระบบส่วนใหญ่ตอบอยู่ดี |

## ระบบที่นำมาเปรียบเทียบ / Baselines and ablations

`run_full_benchmark()` รันทั้งหมดบนชุดเดียวกัน:

| ระบบ | บทบาท |
|---|---|
| `exact_only` | เส้นฐานล่าง — normalise แล้วค้นตรง ๆ |
| `fuzzy_greedy` | เส้นฐานที่ล่อใจ — fuzzy แล้วเอาอันดับหนึ่งเสมอ ไม่เคยงดตอบ |
| `llm_direct` | **ทางเลือกเชิงสถาปัตยกรรม** — ให้แบบจำลองภาษาตอบรหัสเอง |
| `ablate_context` | ตัดสัญญาณบริบทออก |
| `ablate_aliases` | ตัดตารางชื่อพ้องออก |
| `full_resolver` | ระบบเต็ม |

`fuzzy_greedy` สำคัญเป็นพิเศษ เพราะมีอัตราการจับคู่สูงที่สุดและดูดีที่สุดถ้าดูแค่
ตัวเลขเดียว — จนกระทั่งดูคอลัมน์ `fabricated` การใส่มันไว้คือการแสดงว่าเข้าใจว่า
ตัวชี้วัดใดหลอกได้

`llm_direct` ต้องรันด้วยผลจากแบบจำลองจริง `llm_direct_stub()` มีไว้อธิบายการทดลอง
เท่านั้น **ห้ามรายงานตัวเลขจาก stub ราวกับว่าวัดมาจริง**

### ตัวอย่างผลลัพธ์ (ข้อมูลสังเคราะห์ ไม่ใช่ผลจริง)

```
system              acc     unique  prefix  collision  mueang  alias  unresolvable  fabricated
full_resolver       1.000   2/2     1/1     1/1        1/1     3/3    2/2           0
ablate_context      0.800   2/2     1/1     0/1        0/1     3/3    2/2           0
ablate_aliases      0.800   2/2     1/1     1/1        1/1     1/3    2/2           0
exact_only          0.500   2/2     1/1     0/1        0/1     0/3    2/2           0
fuzzy_greedy        0.500   2/2     1/1     1/1        0/1     0/3    1/2           1
```

รูปแบบที่ต้องการคือแบบนี้: ระบบเต็มชนะ **และ** ช่องว่างกระจุกอยู่ในประเภทที่ระบบ
ออกแบบมาแก้ ตารางแบบนี้คือข้อโต้แย้ง ตัวเลขความแม่นยำตัวเดียวไม่ใช่

## การประเมินสองชั้น / Intrinsic + extrinsic

นี่คือส่วนที่ทำให้เก็บงานเชิงนิเวศไว้ได้ทั้งหมด และเป็นจุดแข็งที่งาน NLP ส่วนใหญ่
ไม่มี

1. **Intrinsic** — ความแม่นยำในการระบุตำแหน่ง (ตารางข้างบน)
2. **Extrinsic** — ระบบที่ระบุตำแหน่งแม่นกว่า ทำให้การอนุมานปลายทางดีขึ้นหรือไม่
   ป้อนผลจากแต่ละ baseline เข้าแบบจำลองการแพร่กระจาย แล้ววัดว่าค่าการทำนาย
   จังหวัดถัดไปแบบนอกกลุ่มตัวอย่างต่างกันอย่างไร

ถ้า `fuzzy_greedy` ที่กุตำแหน่งขึ้นมา ทำให้แบบจำลองปลายทางแย่ลงอย่างวัดได้ นั่นคือ
การเชื่อมโยงที่สมบูรณ์: **ข้อผิดพลาดของ NLP ส่งผลต่อข้อสรุปทางวิทยาศาสตร์
อย่างเป็นรูปธรรม** เป็นผลลัพธ์ที่หนักแน่นมากสำหรับสาขาคอมพิวเตอร์

---

## องค์ประกอบเชิงคอมพิวเตอร์อื่นที่วัดได้อยู่แล้ว

อย่าทิ้ง สิ่งเหล่านี้วัดได้และเป็นผลเชิงประจักษ์:

- **การตรวจสอบการอ้างอิงย้อนกลับ** (`verify_grounding`) — วัดว่าคัดระเบียนออก
  กี่เปอร์เซ็นต์ และในนั้นเป็นการกุขึ้นจริงกี่เปอร์เซ็นต์ นี่คือการควบคุม
  hallucination ที่วัดผลได้
- **เส้นโค้งคุณภาพ–ราคา** (`bakeoff.py`) — คุณภาพการสกัดเทียบกับต้นทุนข้าม
  แบบจำลองหลายระดับ บนงานภาษาที่มีทรัพยากรจำกัด
- **ความน่าเชื่อถือของ schema** — อัตราการต้องลองใหม่ระหว่าง schema-constrained
  กับ JSON mode ธรรมดา

## เมื่อกรรมการถามว่า "ส่วนไหนคือวิทยาการคอมพิวเตอร์"

คำตอบที่เตรียมไว้:

> ระบบระบุตำแหน่งทางภูมิศาสตร์จากข้อความภาษาไทยที่มีความกำกวมสูง ผมออกแบบเป็น
> สถาปัตยกรรมผสม โดยให้แบบจำลองภาษารายงานชื่อตามตัวอักษรและให้ตัวจับคู่เชิงกฎ
> เป็นผู้ระบุรหัส แล้ววัดผลเทียบกับ 5 ระบบบนชุดข้อมูลที่ติดป้ายเอง 400 รายการ
> ระบบเต็มได้ความแม่นยำ X% เทียบกับ Y% ของการถามแบบจำลองภาษาโดยตรง และ
> ความต่างกระจุกอยู่ในกรณีชื่อซ้ำและ อ.เมือง นอกจากนี้ยังวัดอัตราการกุตำแหน่ง
> ซึ่ง baseline ที่ไม่เคยงดตอบสูงถึง Z%

ถ้าตอบแบบนี้ได้ ไม่มีใครถามว่าทำไมถึงส่งสาขาคอมพิวเตอร์

## ลำดับงาน / Order of work

1. **ติดป้ายชุดทดสอบ 300–500 รายการ** — ทุกอย่างขึ้นกับข้อนี้
2. รัน `llm_direct` ด้วยผลจากแบบจำลองจริง เพื่อทดสอบ H0/H1
3. รายงานความสอดคล้องระหว่างผู้ติดป้าย
4. วิเคราะห์ข้อผิดพลาด — ระบบพลาดตรงไหนและเพราะอะไร
5. การประเมินปลายทาง — ป้อนแต่ละ baseline เข้าแบบจำลองการแพร่กระจาย

งานเชิงนิเวศทั้งหมดที่ทำไว้แล้วยังใช้ได้ เพียงแต่เปลี่ยนบทบาทจาก "ผลลัพธ์หลัก"
เป็น "การประเมินปลายทาง" ซึ่งในสาขาคอมพิวเตอร์ถือเป็นจุดแข็ง ไม่ใช่จุดอ่อน
